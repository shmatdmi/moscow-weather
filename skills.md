# Инструкции по проекту

## Что это за проект

Это небольшой статический сайт погоды в Москве. Вся пользовательская часть находится в одном файле `index.html`, а публикация выполняется через nginx в Docker.

Файлы проекта:

- `index.html` - HTML, CSS и JavaScript сайта.
- `Dockerfile` - сборка nginx-образа со статическим сайтом.
- `nginx.conf` - конфигурация nginx, которая отдает `index.html`.
- `.dockerignore` - исключения для Docker-контекста.

## Текущая функциональность

Сайт показывает:

- текущую погоду в Москве через OpenWeather API;
- температуру;
- скорость ветра;
- описание погоды;
- время последнего обновления;
- ошибку загрузки, если API недоступен;
- форму авторизации в правом верхнем углу;
- локальную регистрацию и вход без базы данных;
- цвет фона погодной карточки по температуре.

## Архитектура

Проект намеренно простой и не использует сборщики, фреймворки и внешние зависимости на фронтенде.

Основные ограничения:

- не добавлять React/Vue/Angular без явной причины;
- не добавлять backend, если задача решается статически;
- не добавлять базу данных для текущей демо-авторизации;
- сохранять весь UI в `index.html`, пока проект остается небольшим;
- не усложнять Dockerfile, если nginx просто отдает статический сайт.

## Стиль интерфейса

Интерфейс должен оставаться компактным, спокойным и утилитарным:

- основной блок `.weather` расположен по центру экрана;
- форма `.auth` закреплена справа сверху;
- радиусы скругления в основном `8px`;
- цвета задаются через CSS-переменные в `:root`;
- карточки метрик используют светлый фон и тонкую границу;
- на мобильных экранах форма авторизации занимает верхнюю часть, а карточка погоды смещается ниже.

При изменениях важно проверять, что:

- форма авторизации не перекрывает карточку погоды на мобильных экранах;
- текст не вылезает за пределы кнопок и карточек;
- контраст текста остается читаемым при изменении фона погоды;
- новые элементы не ломают сетку `.weather__main`.

## Погодная логика

Погода загружается из OpenWeather:

```js
const apiUrl = 'https://api.openweathermap.org/data/2.5/weather?q=Moscow,RU&appid=ba23e3e7888484e7a26b57b215d65200&units=metric';
```

Обновление происходит раз в минуту:

```js
const updateIntervalMs = 60 * 1000;
```

Температура форматируется через `Intl.NumberFormat('ru-RU')`, время - через `Intl.DateTimeFormat('ru-RU')`.

Фон карточки погоды зависит от температуры:

- минимум шкалы: `-30`;
- максимум шкалы: `38`;
- холодные значения уходят в синий оттенок;
- теплые значения уходят в красный оттенок;
- значения за пределами диапазона зажимаются к ближайшей границе.

Логика находится в функции:

```js
function updateWeatherBackground(temperature) {
  ...
}
```

Если меняется шкала температуры, обновлять нужно `minTemperature`, `maxTemperature` и при необходимости формулу `hue`.

## Авторизация без БД

Авторизация сделана как клиентский демо-вариант без сервера и базы данных.

Данные хранятся в `localStorage`:

- `weatherUsers` - объект пользователей;
- `weatherCurrentUser` - текущий пользователь.

Сейчас пароль сохраняется в простом виде:

```js
users[login] = { password };
```

Это допустимо только для учебного или демонстрационного сайта. Для реального проекта нужно заменить это на серверную авторизацию с хешированием паролей и сессиями.

При доработке текущей версии без БД:

- не обещать пользователю настоящую безопасность;
- не хранить чувствительные данные в `localStorage`;
- не использовать эту схему для продакшена;
- можно улучшить UX: подсказки, валидацию, очистку ошибок, отображение имени пользователя.

## Кодировка

Файл `index.html` содержит русские строки и объявлен как UTF-8:

```html
<meta charset="utf-8">
```

Если в терминале русские строки выглядят как `РџРѕРіРѕРґР°`, это проблема отображения кодировки в консоли, а не обязательно проблема файла. Перед массовыми заменами текста нужно убедиться, что редактор сохраняет файл в UTF-8.

Важно:

- не переписывать весь файл только ради исправления отображения в терминале;
- при точечных изменениях лучше опираться на ASCII-контекст CSS/JS;
- после правок открывать страницу в браузере и проверять русский текст визуально.

## Docker и nginx

Dockerfile использует официальный образ:

```dockerfile
FROM nginx:1.27-alpine
```

В контейнер копируются:

- `nginx.conf` в `/etc/nginx/conf.d/default.conf`;
- `index.html` в `/usr/share/nginx/html/index.html`.

nginx настроен так, чтобы все маршруты отдавали `index.html`:

```nginx
location / {
    try_files $uri $uri/ /index.html;
}
```

Для текущего статического сайта этого достаточно.

## Как проверять изменения

Минимальная ручная проверка:

1. Открыть сайт в браузере.
2. Убедиться, что загружается погода.
3. Проверить цвет карточки при полученной температуре.
4. Зарегистрировать тестового пользователя.
5. Выйти и войти снова.
6. Обновить страницу и проверить сохранение текущего пользователя.
7. Проверить мобильную ширину около `420px`.

Docker-проверка:

```powershell
docker build -t moscow-weather .
docker run --rm -p 8080:80 moscow-weather
```

После запуска сайт должен быть доступен по адресу:

```text
http://localhost:8080
```

## Правила будущих изменений

- Сохранять простоту проекта.
- Предпочитать точечные изменения в существующих CSS-классах и JS-функциях.
- Не добавлять новые файлы без явной пользы.
- Не хранить API-ключи и пароли в продакшен-коде.
- Не превращать клиентскую авторизацию в видимость настоящей безопасности.
- При расширении проекта сначала решить, остается ли он статическим или появляется backend.
- Если появляется backend, перенести авторизацию и API-ключ OpenWeather на сервер.
